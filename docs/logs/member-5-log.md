  متجاهلاً ترتيب `existingSections` الفعلي (الذي يحمل ترتيب الآدمن اليدوي من `SectionsManager.jsx`).

  فعلياً (تعديل مادة موجودة). لمادة جديدة كلياً، `SECTION_ORDER` يبقى الافتراضي الأول فقط.

  منطق GitHub جديد، فقط إضافة الملف الجديد لنفس مصفوفة `pdfFiles` بنفس المسار. تحقق نوع صارم قبل
  القبول (pdf↔pdf فقط، image↔image فقط) برسالة خطأ واضحة عند المخالفة.

  النوع. أضفت `hasScheduleValue()` محلية لأن الفحص القديم `Boolean(x)` وحده كان سيتعامل مع مصفوفة
  فارغة `[]` كقيمة "موجودة" (صحيحة منطقياً بجافاسكربت رغم كونها فارغة فعلياً) فيُبقيها بالخطأ بدل
  حذفها. نفس نمط الحفظ التلقائي لـ `sectionProfessors` بلا أي فرق آخر.

- عنصر بدون `type` = `"pdf"` دائماً (توافق عكسي، بلا استثناء) — اختبرته صراحة.
- تحقق `url` (يبدأ `http://` أو `https://`) مُطبَّق هنا بكودي أيضاً، إضافة لتحقق واجهة عضو 3 — حسب العقد المشترك ("كلا الطرفين معاً، لا تكتفِ بأحدهما"). رابط غير مطابق يرمي خطأ واضح بدل نشر بيانات فاسدة.
- مجلد الملفات الفعلية بقي بلا تغيير اسم: `public/pdf/{slug}/` حتى لملفات `image` (لم أُنشئ مجلداً منفصلاً لها).
- عمّمت `sanitizeFileTitle` لتشيل أي امتداد معروف (`pdf`/`png`/`jpg`/`jpeg`/`webp`) لو كتبه الآدمن بنفسه بالعنوان، بدل `.pdf` فقط سابقاً (تفادي `title.png.png` مثلاً).
